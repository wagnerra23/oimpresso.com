## 0. Situação (não é migração de Blade)

`/manage-modules` do UltimatePOS **já foi substituído**: existe `/modulos` em Inertia (`Modules/Index`) com toggle/install/uninstall em POST, e `LegacyMenuAdapter` mapeia `/manage-modules → /modulos`. Logo isto **não é onda de tradução** — é onda de **acabamento + prova**: a tela está implementada, o charter está `draft`, e **`Index.casos.md` não existe** (o gate `ciclo-completo` reprova por isso).

Grupo de middleware da rota (web.php:911): `web · setData · auth · SetSessionData · language · timezone · AdminSidebarMenu`. Autorização hoje é no construtor do controller: `session('is_admin')` **ou** `hasRole('Admin#'.$businessId)`.

## 1. Charter — reforço do que o draft não fecha

**Missão** (mantida): visão única dos módulos nWidart do app com seu estado, para superadmin, sem CLI e sem AdminLTE.

**Regras de domínio (11)**

| # | Regra | Onde vive |
|---|---|---|
| R1 | Fonte do estado ativo/inativo é `modules_statuses.json` na raiz — não o banco | `ModuleManagerService::readStatuses()` |
| R2 | Só aparece na lista módulo que tem **pasta** em `Modules/` — chave órfã no JSON (Accounting, CustomDashboard, Ecommerce, FieldForce, Hms, InboxReport) não é linha | `list()` itera `File::directories()` |
| R3 | `registered` = a chave existe no JSON; ausente ⇒ status **Não registrado** (âmbar), não "inativo" | `list()` + `rowStatus()` |
| R4 | Ordem canônica: ativos primeiro → área → nome | `usort` em `list()` |
| R5 | Área é heurística por palavra-chave no nome (fallback "Outros") — não é metadado do módulo | `guessArea()` |
| R6 | `version` sai de `module.json`; **nenhum dos 32 declara `version`** ⇒ a tela mostra `v0.0` para todos | `list()` fallback `'0.0'` |
| R7 | Escopo é **app-wide/cross-tenant** — sem `business_id` scope (exceção documentada ADR 0093 §superadmin) | charter + controller |
| R8 | Instalar = ativar + `module:migrate --force` + (se existir) `<alias>:install` com `--business` da sessão ou `--all` | `install()` |
| R9 | Desativar **preserva as tabelas** — nunca há drop | `uninstall()` |
| R10 | Toggle e install limpam `cache:clear` + `config:clear` | `setActive()` |
| R11 | Toast vem de `->with('status', [...])` e chega na página como prop `flash` (mapeada em `HandleInertiaRequests`); a tela recarrega só `['modules','flash']` | controller + middleware |

**Non-Goals** (do draft, para [W] ratificar) — não habilita módulo por negócio (isso é pacote no superadmin), não aplica `business_id`, não é para usuário comum, não instala/remove código.

**Anti-hooks** — não grava em GET, não dispara deploy, não ativa módulo para negócio sem passar pelo fluxo de pacote.

**Acréscimos que proponho ao charter** (viram `status: live` junto):
- A1 — a tela **nunca** mostra enum cru: `active|inactive|errored|unregistered` só aparecem como Ativo · Inativo · Com erro · Não registrado.
- A2 — ação destrutiva diz a consequência antes: "as tabelas do banco são PRESERVADAS".
- A3 — cabe em 1280px sem scroll horizontal com a sidebar de 256px aberta (a descrição trunca, a coluna encolhe).
- A4 — detalhe é **drawer lateral (PT-02)**, nunca modal full-screen.

| UC-MOD-11 | Install falha (migration com erro) | toast de erro com a mensagem do Artisan; **estado permanece ativo** (o `setActive(true)` acontece antes) — a linha não pode mentir "instalado" |
| UC-MOD-12 | Desativar pelo kebab | confirm cita a preservação das tabelas; toast "desativado (tabelas preservadas)" |

Fora de escopo declarado: instalar módulo que não existe em `Modules/` ⇒ `InvalidArgumentException` (o Service já valida) — cobrir como teste de borda, não como UC de tela.

2. `index` como usuário sem admin ⇒ 403. Sem sessão ⇒ 401.
3. `index` como `Admin#<biz>` (Spatie, sem `is_admin` na sessão) ⇒ 200 — as duas portas de autorização provadas.
4. `toggle` sem `active` ⇒ 422; com `active` não-booleano ⇒ 422.
5. `toggle` grava o JSON: chave alterada, **arquivo continua ordenado** (diff estável) e as demais chaves intactas.

7. `uninstall` **não** derruba tabela: tabela conhecida do módulo continua existindo depois.
8. Cross-tenant: mudar de business não muda o resultado de `index` (é app-wide por desenho — o teste trava a exceção do ADR 0093 para que ninguém "conserte" com scope).

**Unit — `ModuleManagerServiceTest`**

10. `list()` ordena ativos→área→nome; chave órfã no JSON não vira linha; pasta sem chave vira `registered:false`.
11. `runModuleInstallCommand()`: sem `InstallCommand.php` ⇒ `null`; comando não registrado ⇒ string `[skip]`.

## 6. Decisões pendentes [W] (bloqueiam `status: live`)

- **D1 — `version` sempre `v0.0`.** Nenhum `module.json` declara `version`. Opções: (a) mostrar a versão instalada de `System::getProperty('<alias>_version')` (é o que o `isModuleInstalled()` usa) e reservar `module.json` para versão de código; (b) passar a declarar `version` nos 32 `module.json`; (c) esconder a versão. Recomendo (a).
- **D2 — quais ações o ActionsMenu expõe e com qual RBAC** (pendência do próprio charter). Hoje a porta é `is_admin`/`Admin#biz`, mas existe a permissão `manage_modules` (usada pelo `/manage-modules` legado e pelo item de menu em `AdminSidebarMenu.php:809`). Recomendo unificar em `manage_modules` para não haver duas leis.
- **D3 — o drawer de detalhe entra na produção?** Ele resolve a descrição truncada e é o padrão PT-02; se [W] disser não, a coluna precisa de tooltip.
- **D4 — install roda migration dentro do request web.** Sem fila e sem timeout declarado: um módulo com 24 migrations pode estourar o `max_execution_time` e deixar a UI mentindo. Opções: job em fila com estado "instalando", ou lock + limite declarado.
