## 0. Situação — isto É onda de tradução

O admin do CMS ainda é **Blade/AdminLTE puro**: `cms::page.index|create|edit` (widgets `box-solid`, TinyMCE, `fileinput`, `swal`, `toastr`, jQuery `$.ajax` no delete) e `cms::settings.index` com as 8 `partials`. O lado **público** já é Inertia (`Site/Page`, `Site/Home`, blog), com os `/old` como fallback Blade — ou seja: **o site já migrou, o painel não.**

Rotas administrativas (prefixo `cms`, middleware `web · SetSessionData · auth · language · timezone · AdminSidebarMenu · superadmin · throttle:60,1`):
`cms/install{,/update,/uninstall}` · `cms/cms-page` (resource, exceto `show`) · `cms/site-details` (resource).

## 2. Regras de domínio (13) — o que a tela precisa obedecer

| # | Regra | Onde vive |
|---|---|---|
| R1 | Um único CRUD serve 3 tipos: `type = page \| blog \| testimonial` (query `?type=`) | `CmsPageController::index/create/edit` |
| R2 | Rótulo do formulário muda por tipo: em `testimonial`, título = **nome de quem depõe** e conteúdo = **depoimento**; imagem = **foto** | `page/create.blade.php` `@php` |
| R3 | `layout` preenchido (`home`, `contact`) = **página de sistema**: o botão de excluir não existe | `page/index.blade.php` `@if(empty($page->layout))` |
| R4 | Em `layout=home`, e só nela, aparecem os blocos `feature` e `industry` (ícone + título + descrição por item) | `page/partials/{features,industries}` + `CmsPageMeta` |
| R5 | Em `layout ∈ {home, contact}` o rótulo do corpo vira **Descrição** | `page/edit.blade.php` |
| R6 | `priority` ordena a listagem (asc); vazio vai pro fim | `index()` `orderBy('priority')` |
| R7 | `meta_description` vazia é preenchida com os **160 primeiros caracteres** do conteúdo, em texto puro | JS do `create/edit.blade` |
| R8 | O conteúdo é **sanitizado na renderização pública** (`SiteContentService::sanitizeHtml`) porque `Site/Page` usa `dangerouslySetInnerHTML` | `showPage()` |
| R9 | Endereço público sai do **título**: `/c/page/{title com espaços → hífen}`; blog é `/c/blog/{slug}-{id}`; sem registro ⇒ **404 antes de qualquer render** | `showPage()` `abort(404)` |
| R10 | Trocar a imagem de destaque **apaga o arquivo anterior** do disco | `update()` `unlink()` |
| R11 | Criar/editar/excluir gravam log estruturado (`cms.page.created/updated/deleted`) com PII redactada; `CmsSiteDetail` tem activitylog (LGPD Art. 37/38) | controller + `PiiRedactor` + `LogsActivity` |
| R12 | Modo demo **bloqueia** store/update/destroy (`notAllowedInDemo`) | controller |
| R13 | Formulário público: honeypot `_gotcha` deve vir **vazio** (bot cai fora em silêncio), `throttle:60,1` por IP, e o lead só notifica se houver `notifiable_email` **e** mensagem | `SubmitContactFormRequest` + `CmsLeadService` |

**Acréscimos que proponho ao charter** (F1 já implementa; [W] ratifica):
- A1 — nada de enum cru na UI: `page/blog/testimonial` e `is_enabled` aparecem como **Páginas · Blog · Depoimentos** e **Publicada · Rascunho**.
- A2 — mudar o título avisa **antes** que o endereço muda e o link antigo quebra (R9 é um 404 de verdade).
- A3 — a sanitização é **declarada, não silenciosa**: a tela lista o que será removido (script, iframe, atributo de evento).
- A4 — ordem se muda por **arrasto**, e o arrasto é bloqueado com filtro/busca ativos, dizendo o motivo.
- A5 — detalhe é **drawer lateral (PT-02)**, nunca modal full-screen.
- A6 — o painel do CMS é PT-BR; o seed em inglês do UltimatePOS **não** é copy aceitável.

## 3. Casos de uso (18) — com critério de aceite

| UC | Caso | Critério de aceite |
|---|---|---|
| UC-CMS-01 | Superadmin abre `/cms/cms-page?type=page` | 200 + lista ordenada por `priority` asc; contadores por tipo no header |
| UC-CMS-02 | Usuário sem `superadmin` abre qualquer rota `/cms/*` | 403; nenhuma prop de conteúdo vaza |
| UC-CMS-03 | Visitante sem sessão | 401/redirect de login |
| UC-CMS-04 | Cria página sem título | erro inline no campo (`title` required); nada é gravado |
| UC-CMS-05 | Cria página com `meta_description` vazia | grava os 160 primeiros caracteres do conteúdo em texto puro (R7) |
| UC-CMS-06 | Cola HTML com `<script>`/`onclick` | a tela avisa o que será removido; o público renderiza sem eles (R8) |
| UC-CMS-07 | Edita título de página já publicada | aviso do novo endereço; após salvar, o endereço antigo devolve 404 (R9) |
| UC-CMS-08 | Abre página com `layout=home` | aparecem os blocos `feature` e `industry`, editáveis item a item; em página livre, não aparecem (R4) |
| UC-CMS-09 | Tenta excluir página de sistema | botão indisponível com o motivo; a rota também recusa (R3) |
| UC-CMS-10 | Exclui página livre | remove o registro, apaga a imagem de destaque, loga `cms.page.deleted` (R10/R11) |
| UC-CMS-11 | Troca a imagem de destaque | o arquivo anterior deixa de existir no disco (R10) |
| UC-CMS-12 | Reordena por arrasto | nova ordem = ordem do site; com filtro/busca ativos o arrasto é bloqueado com motivo (A4) |
| UC-CMS-13 | Seleciona N linhas e publica/tira do ar | ação em lote aplica só ao permitido; página de sistema não é excluída em lote |
| UC-CMS-14 | Ambiente demo tenta salvar | bloqueio de demo, mensagem clara, nada gravado (R12) |
| UC-CMS-15 | Visitante envia o formulário de contato | 200, notificação pro `notifiable_email`, log com PII redactada; sem e-mail configurado ⇒ lead salvo + aviso na tela de Leads (R13) |
| UC-CMS-16 | Bot preenche `_gotcha` | rejeitado silenciosamente; não gera lead nem notificação (R13) |
| UC-CMS-17 | 61ª requisição no mesmo minuto por IP | 429 (throttle) |
| UC-CMS-18 | `cms:health` sem nenhuma página publicada | exit 1 + `cms:health ALERT` no log; com `--detail`, uma linha por check |

## 4. Ondas para [CL] (ordem de aplicação)

**Onda 1 — Páginas/Blog/Depoimentos em Inertia** (mata `page/index|create|edit.blade.php`)
`Modules/Cms/Resources/js/Pages/Admin/Content/Index.tsx` + `Editor.tsx`; `CmsPageController::index/create/edit` passam a `Inertia::render`; `DataTablePro` + `TabBar` + `PageHeader` + `Drawer`; TinyMCE sai — editor de HTML com prévia (computador/celular) como no F1. Mantém as rotas atuais.

**Onda 2 — Detalhes do site** (mata `settings/index.blade.php` + 8 partials)
Uma página com rail de 8 seções e um único POST (`CmsSiteDetail::createOrUpdateSiteDetails` já aceita o payload inteiro). Campos idênticos aos do F1 (nomes preservados: `notifiable_email`, `contact_us[]`, `mail_us[]`, `follow_us{}`, `statistics{}`, `faqs[]`, `chat{}`, `chat_widget`, `google_analytics`, `fb_pixel`, `custom_js`, `custom_css`, `meta_tags`, `btns{}`).

**Onda 3 — Leads** (tela nova, endpoint já existe)
Precisa de **persistência**: hoje `CmsLeadService` só notifica e loga — o lead não é gravado. Proponho `cms_leads` (name, email, mobile, message, origin_url, notified, status, created_at) + ligação com o CRM. **Decisão pendente de [W]:** tabela nova no Cms ou lead direto no `Modules/Crm`?

**Onda 4 — Módulo** (`cms/install`, `cms:health`, `cms:import-wp-officeimpresso`)
Instalar/atualizar/desinstalar via `BaseModuleInstallController` (já existe), os 3 checks do health expostos na tela, e o importador WP com **simulação ligada por padrão** (o comando tem `--dry-run`; falta a ponte HTTP).

**Onda 5 — prova**
`Content/Index.charter.md` + `.casos.md` com os 18 UC acima, `prototipo-ui/contrato/cms.contract.json` (ADR 0286) com as seções e a copy literal, e os testes: os `Wave2*CmsSaturationTest` já cobrem o público — falta Feature test do **painel** (403/401, demo, honeypot, 404 pós-rename).

## 5. Pedidos de DS (sem eles, F3 improvisa)

1. **`StatusBadge kind="cms"`** — `publicada · rascunho · pagina-sistema · sem-descricao` (hoje o F1 usa pill bespoke).
2. **`Input`/`Textarea` com `ref` + acesso à seleção** — necessário pra inserir tag/atalho no cursor (mesmo pedido já registrado por `notificacoes-page.jsx`).
3. **Componente de reordenação por arrasto** (`SortableList` ou `DataTablePro reorderable`) — o F1 fez à mão; `priority` aparece em Cms, produtos e FAQ.
4. **`ProofFrame`/prévia de dispositivo** — a prévia em celular do editor é bespoke (`.cms-ed-prev.mob`).

## 6. O que NÃO fazer

- Não reintroduzir TinyMCE (o corpo é HTML sanitizado; o editor rico volta só com decisão de [W]).
- Não usar modal full-screen pro detalhe (PT-02: drawer).
- Não deixar copy em inglês do seed do UltimatePOS chegar ao cliente.
- Não gravar em GET, não emitir enum cru, não excluir página de sistema por rota alternativa.
